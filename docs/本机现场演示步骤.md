# 在本机练习面试现场演示

这次先把信息科技《循环结构》跑通。面试重点是当场处理一段新需求、代码真的运行、教案保存到本机，以及说清老师还要检查什么。语文数学可以作为补充，不要分散主流程。

## 一 先启动桌面端

这台电脑已经有Python和窗口组件，项目根目录的.env也已配置API。请保留.env在本机，不要分享。

1. 打开项目目录 `D:\桌面\面试测试题`。
2. 双击 `start-desktop.cmd`。也可以在这个目录运行 `python desktop.py`。
3. 小窗口里输入 `D:\桌面\面试测试题\onsite_workspace`。这台电脑上已创建这个空文件夹，专门练现场演示，和以前的测试记录分开。换电脑时请先新建一个空文件夹，再填它的实际路径。
4. 点击“打开工作区并开始备课”。浏览器会打开本机页面，点击“体验产品能力”。
5. 展开“工作区文件与修订”，确认路径是onsite_workspace，模式是desktop。小窗口要保持开启，关掉它服务就停止。这个桌面版是原生目录启动窗口加本机浏览器页面。

如果只是先试功能，也可以打开Docker Desktop，双击start-docker.cmd，访问 http://127.0.0.1:8765 。但为了满足“桌面端当场能跑”，请务必自己把上述桌面启动方式也练一遍。

## 二 输入现场给出的需求

选择“信息科技”“初中”，课题填“循环结构”，总时长选40分钟，生成方式选“真实模型API”。先不要上传以前的教案，看看仅凭这段新需求能否备课。

可以先复制这段练习：

> 下周三给初二上一节《循环结构》，班里刚学完条件语句，上次练习5人没交、3人写了死循环，帮我出这节课。按40分钟安排，提供两个示例和基础、进阶、挑战各一道练习，附参考答案与评分点。重点安排课前诊断、变量追踪和终止条件练习。总人数和边界错误人数没有提供，不要编造；未交原因未知，不等于不会。

展开“调整班情数据或导入文件”，把JSON换成：

```json
{"total":null,"missing":5,"infinite_loop":3,"boundary":null}
```

这里null表示“没有提供”，不是0。面试官给了新人数，就按新信息填写；不要把默认示例的40人、6人边界错误带进真实需求。人数可以重叠，不能把5人和3人简单相加理解成8个不同学生。

点击“生成/继续修改”，等待结果。真实模型需要联网并使用账号额度。不要连续点按钮；报错时先看页面原因，不要把离线模板说成真实生成。

## 三 检查生成的内容

1. 有一份教案、两个代码示例、三道分层练习，课时相加是40分钟。
2. 教案应考虑刚学完条件语句，先做简短摸底，不直接跳到复杂循环。
3. 5人未交应引出诊断或补练，不能写成“这5人基础差”。
4. 3人死循环应对应初始化、判断条件、变量更新，以及先手算变量表再运行。
5. 未提供的边界错误人数和班级总人数应保留未知；边界题可以作为常规练习，不能编造“本班已有6人出错”。
6. 展开每段代码的执行详情，确认有真实输入、预期输出和实际输出，且全部通过。用例数看本次实际结果，不要求每次恰好16条。

如果内容不贴合，直接继续提出修改要求，例如：“先保留基础和进阶题，把挑战题换成读书打卡；死循环示范增加一张变量追踪表，总时长不变。”修改后重新看运行结果和审核状态。

## 四 故意改错 检查能不能挡住

先在历史记录中记住一个通过版本的编号。打开一个示例代码编辑框，临时改成：

```python
while True:
    pass
```

点“保存修改并重新验证”。应该看到执行超限或疑似死循环，页面显示验证失败。此时尝试“下载教案包”，系统必须拒绝；也不能接受条目。

然后到“工作区文件与修订”恢复刚才通过的版本。恢复后接受状态会清空，需要重新检查再确认。

这段是演示故意制造的错误，要这样向面试官说明，不能说它是AI刚才自然生成的错误。

## 五 老师确认 保存到本机

1. 看完6项内容后逐项点“接受”，确认显示已接受6/6。
2. 点“预览写入差异”，看清将增加或覆盖哪些文件。
3. 点“确认写入”。已有文件会先备份。
4. 用资源管理器打开 `D:\桌面\面试测试题\onsite_workspace\published`，确认能看到lesson.md、示例代码、练习和检查报告。
5. 点“下载教案包ZIP”，检查压缩包里也有对应材料。

关闭桌面启动小窗口，再双击start-desktop.cmd，输入同一个onsite_workspace路径。确认历史版本、对话和审核状态恢复，published里的教案仍在。不要换成另一个空文件夹，否则看到的会是另一份工作记录。

## 六 现场怎样解释结果

可以用自己的话说：

> 目前可信的是：这些代码确实在列出的输入下运行过，结果与期望一致；死循环会被停止，失败时不能导出；确认后的文件也确实保存在本机，有版本和修改记录。
>
> 还需要老师看的是：题目期望答案是否正确、测试有没有漏情况、讲解是否准确、难度和节奏是否适合本班。代码通过不能证明整份教案没有错误。
>
> 这次已知的是5人未交、3人死循环。所以先摸底未交原因，再安排变量追踪和终止条件示范。其他错因只是教学假设，不能当作本班已经发生的事实。

如果新需求变了，先检查新产出是否真的跟着变。例如把死循环人数改为0，不能还把“本班3人死循环”作为预警依据；没有未交者时，也要检查是否仍机械安排同一份补交活动。

## 七 面试前和提交时

面试前用这台电脑、同一个启动方法、同一网络，完整走一次。提前准备好Python、API配置和一个空教案目录；保留本机视频，以便网络问题时说明已实现的流程。真实模型生成需要外部网络，本机保存和代码运行本身不依赖公开演示网站。

收到题目后的48小时内，提交[作业提交页](../作业提交.md)里的四类入口：Web URL、公开仓库、唯一演示视频、一页设计文档。截止时间从你实际收到题目的时间算，不是从最后更新Git的时间算。

你自己练完时，最值得确认的是：桌面能开、真实新需求能生成、代码真能跑、错误真被挡、文件真落到本机、重开记录不丢，以及你能解释老师为什么仍须审核。
