# 我怎样给AI提要求

这里的prompt，就是“发给AI的具体要求”。项目开发由Codex协助完成；产品里生成教案用的是qwen-plus。下面记录的是产品生成教案时的主要要求和修改办法。

## 先说清要交什么

例如老师的需求：

> 给初二备一节40分钟的循环结构课，刚学完条件语句。全班40人，5人未提交作业，3人写了死循环，6人把循环范围写错。请给出教案、两个代码示例，以及基础、进阶、挑战各一道练习，附参考答案和评分点。

程序还会给AI一份固定格式，要求各项内容填写齐全，代码附测试输入与正确输出。具体原文保存在 `app/core.py` 的 `SYSTEM` 中，可以随Git历史查看。

每次还会提供上一版教案、最近8条对话，以及教案目录里最多30份小型文本资料，帮助它继续修改。完整记录保存在本机，不是每次全部发给模型。

## 代码运行失败时，给具体结果

程序会把失败的输入、应该输出什么、实际输出什么发回AI，再要求修正。最多调用3次；没有修好就展示失败，不能直接导出。

演示中也做了一个人为错误：删掉while循环里的 `i += 1`。程序因为循环不结束而停止运行，并阻止下载。离线模式先生成一版，再输入“故意失败”可以看到这个效果。这是特意做的测试，不是模型自然写错的记录。

## 教案说得不清楚时，也要具体指出来

真实教案曾写“逐个检查边界”，我要求它补充老师问什么、学生写什么、答案是什么、答错后怎么教。补写后又发现它把循环结束时的变量值讲错，就列出输入0、1、5对应的正确值，让它修正。

[完整案例](AI修正案例.md)写了怎么发现和修改；[原始记录](evidence/education-revision.json)保留了两轮指令、修改前后内容、模型返回编号和检查结果。里面用的是演示班情，没有真实学生信息。

其他真实调用的详细结果保存在本机 `demo_evidence/live/`。密钥和本机聊天记录没有上传到公开仓库。
