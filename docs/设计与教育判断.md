# 设计与教育判断（一页概要）

**服务初二教师，先解决循环结构备课。** 相比做完整IDE，先把40分钟教案、2段示例、3道分层练习、参考答案与评分点连成一个可验证包。大学配置用于对照适配，不宣称覆盖完整课程。

**错误如何被挡住。** 模型只产生草稿；每段示例和参考解至少3条输入输出用例，独立进程真实运行。错误定位到条目和用例，死循环触发步数/时间限制。存在失败时禁止接受、下载和发布；最终交付再次复验。逐项教师审核负责课程适配、题目期望和措辞，测试通过不是正确性证明。修订、拒绝、恢复、发布都有审计，正式覆写先看diff并备份。没有任意shell和删除工具。

**班情先于内容。** 5人未交进入前置诊断，不等同“不会”；3人死循环增加变量追踪和终止条件示范；边界错因安排0、1和端点用例。结构化警告包含统计证据、触发原因和干预动作。

**48小时取舍。** 砍掉账号、学生端、IDE、任意代码运行、多Agent、多租户与学校系统对接。用标准库Web+Tk启动器共用引擎；离线演示明确标识。保留模型API、真实执行、修订与人工确认这一主线。提供公网体验、Docker部署、原生目录启动与84秒实际录屏。

**如何使用AI。** 关键prompt：“返回严格JSON；每段代码有边界用例；根据5缺交、3死循环安排诊断与追踪；收到真实失败报告后修复对应条目。”真实案例：模型教案写“逐个检查边界”过于空泛，要求补出检查标准后，又把while退出时的i写成n；代码16条用例仍全通过。人工对照代码发现错误，反馈n=0/1/5时的具体状态，模型改为i=1/2/6；另加3条独立执行核对。前后产物和prompt见[修正记录](AI修正案例.md)。视频另有人工删除`i += 1`的死循环实验，明确区分人为注入与模型真实错误。

**未来学生开放。** 教师发布任务时锁定参考答案；学生界面先要求预测、变量表和已有尝试，再按错因逐级提示，最后才给相似题。学生不接触教师API、参考解文件或工作区；是否揭示答案由教学策略和教师控制。以解释与迁移任务衡量学习，不以过用例等同掌握。

**真实班级首迭代。** 邀请教师逐条审校课程目标、题库独立测试和超纲白名单；上线前完成租户鉴权、容器隔离、审计防篡改、数据删除与保留策略。只收聚合学情，禁止姓名、学号、作业原文上传外部模型；必要个人信息应有学校授权与监护人知情流程。预警避免能力标签，所有对学生可见内容须经教师确认。

独立实现，未引用Codex源码；架构参考官方 [Agent Loop](https://openai.com/index/unrolling-the-codex-agent-loop/) 与 [开源仓库](https://github.com/openai/codex)。
