# 语文 数学 信息科技怎样使用

这一版可以在工作台直接选择三门学科。原来的编程备课还在，语文和数学有各自的内容格式，也会明确告诉老师机器检查了什么。

## 先走一遍

1. 选择学科，再填课题、学段和总时长。例如语文、小学、jqx、40分钟。
2. 写清具体年级、这次备第几课时、学生已经学过什么。只有学段还不够判断难度。
3. 有旧教案时，展开“参考教案”，选择docx、txt或md。程序先提取文字供你检查，也可以直接粘贴。图片、口型图、四线三格和排版不会被读懂。
4. 删除姓名、学校、学生信息等不需要的内容。程序会隐藏部分标有“执教人”等的整行，但不能保证识别所有个人信息，仍须自己看一遍。
5. 想按自己的资料改写，请在本机选“真实模型API”。公开网页和离线模式只展示固定示例，不会按上传资料重新编写。
6. 看完每项示范、练习和参考答案，再点“接受”。需要修改时可以直接编辑文字；数学也可以修改供核对的算式。修改后审核状态会清空。
7. 全部6项确认后下载。本机版还可以预览文件改动并保存到老师的教案目录。

## 三科分别检查什么

|学科|生成的内容|自动检查范围|需要老师判断|
|---|---|---|---|
|语文|教学活动、文字示范、分层练习、参考答案和观察点|这些材料是否填写齐全|拼音、口型、笔顺、书写、写作质量和课时安排|
|数学|示范、题目、答案、理由、评分点和算式|列出的整数或分数四则算式是否算对|题意、图示、单位、推理、步骤以及文字答案与算式是否一致|
|信息科技|教案、Python示例、分层题、参考解和测试|代码在指定输入下的输出、超时等错误|测试期望是否对，讲解和难度是否合适|

语文不会显示“所有知识都已验证”。数学算式全对，也可能把题意理解错；程序目前不会自动证明整个解题过程。三科最终都要老师确认。

## 离线示例目前有哪些

- 语文：小学jqx、习作漫画老师；初中语文示例采用写作活动。
- 数学：小学乘法的初步认识、初中一元一次方程。
- 信息科技：循环结构，按学段调整讲解；这里运行的是Python，不是Scratch。

总时长可以选35、40、45、80或90分钟。80分钟表示本次材料的总时间，不代表离线示例已经自动分成两节设计好的课。准备两个课时，请在真实模型需求中明确每课时的目标与时间，最后人工核对。

支持三门学科，不等于覆盖全部教材。离线模式改课题文字不会变出一套新课。其他课题可用真实模型生成草稿，但仍要检查内容和难度。

## 这次实际做了哪些测试

三科都真实调用了qwen-plus：信息科技16项代码测试通过；数学10项列出算式核对通过；语文检查了5项材料的内容和教师检查点是否填写，不把它算作拼音知识正确性验证。[调用结果摘要](evidence/multisubject-live.json)

原来的4项程序测试加上新增5项，共9项通过。浏览器与Docker还实际走过学科切换、Word读取、下载、错误拦截和记录恢复。数学故意把正确算式的期望改错时，系统算出不一致并阻止导出；原有死循环拦截也保留。[界面检查摘要](evidence/multisubject-browser.json)

## jqx教案里发现了什么

参考Word只提取了文字，没有识别插图。模型第一版把q、p的字形位置讲错，还把第二课时的ü省点放进第一课时挑战题，甚至出现前后矛盾的评分说明。材料填写检查没有发现这些知识问题，是人工审核发现后要求改写的。

修订后改为标准字形并排比较，挑战题改成已学音节的换卡活动，读音和书写仍交给老师判断。提交示例又人工调整了发音提示和换卡次数，保留“待审核”标记。原资料声母数量与列举不一致，也提醒老师核对，不能直接照抄。

班情提醒只引用老师填写的汇总人数，具体错因明确写为待课堂核实的假设，不能虚构某几位学生具体错了什么。
