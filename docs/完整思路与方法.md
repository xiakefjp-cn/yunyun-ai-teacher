# 从题目到可演示系统

目标学段选初中：题目给出明确的初二班情，变量、条件、计数和累加可以用少量输入输出用例检验；课堂可用性比泛化编程能力优先。大学适配作为对照配置，不宣称覆盖大学完整教学大纲。

实现顺序：先固定输出协议与发布门禁，再实现执行器、修订与审核；随后把班情映射到课堂干预；最后接入模型和双端界面。这使模型失败也不会绕过系统规则。

数据流：教师需求+聚合班情+工作区资料 → 共享引擎 → 离线模板或模型 → JSON结构校验 → 真实代码测试 → 失败反馈修复（至多3轮） → 草稿修订 → 教师接受/拒绝 → 复验 → ZIP或确认落盘。

`runner.py` 用正向AST语法限制，独立隔离模式Python进程、临时工作目录、极小内置函数表；有3万追踪事件、2秒墙钟、12000字符输出限制。Windows Job Object / Linux资源限制设128MB进程内存。模型不能调用shell、网络、文件或导入模块。这不是通用安全沙箱，公网服务还需操作系统/容器级隔离。

`core.py` 管理固定协议、聚合班情校验、API调用、有限修复循环和审计。API只支持模型提出整包修订，工具由编排器固定调用；未实现Codex式任意多工具自决策。这样将48小时范围收敛到可测试主线。

`server.py` 使用标准库HTTP服务，`desktop.py` 用Tk选择本地目录并启动同一个服务。老师从同一套界面完成两端流程，减少行为分叉。单教师模型是明确边界，不冒充多租户Web产品。

班情不只是提示词：缺交人数改变前置诊断时间，死循环人数改变追踪示范时间；警告保留实际统计证据、触发原因、干预动作。缺交原因未知，不据此贴能力标签。大学版本引入不变量、终止性、复杂度比较，初中使用点名计数和变量表。测试只验证数字变化和课程40分钟约束，课程深度还要专业教师评阅。

权限与可信度分层：代码在用例上运行一致是机器证据；题目期望正确、表述适龄和课堂节奏属于教师责任；修订号、审计、报告和清单帮助追溯。恢复旧版不会继承旧审核，避免老师无意发布未经重审内容。

上下文策略保留完整磁盘记录，仅向API发送最近8条会话+最新产物+最多30个小型文本文件。窗口有界但无精细token预算；后续加入检索和语义摘要。系统提示保持固定前缀，不在每次改写工具表；缓存收益未测量。

开发与验收建议：首先跑无密钥离线链路；再用真实key检查自由语言“换一个例子”“降低挑战难度”多轮修改；现场演示必须加入故意死循环与发布受阻；最后检查真实文件目录、恢复会话和包内验证报告。不能把自动化脚本录像替代产品界面录像。

参考架构思想：[Codex Agent Loop](https://openai.com/index/unrolling-the-codex-agent-loop/)、[Codex源码](https://github.com/openai/codex)。本项目独立实现，未复制或改写其源码；借鉴循环、共享核心、审批和恢复思想。
