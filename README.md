# 耘耘AI助教

现在可以选择语文、数学和信息科技。老师填写课题、学段和时长，也可以读取已有Word教案作为参考，整理出教案、两个课堂示范和三种难度的练习。机器能检查的内容因学科不同，最后都要老师逐项确认。

## 题目从哪里来

现在可以选择：大模型根据需求出题并给解答、直接使用题库、题库优先由模型补齐。纯模型模式只发送空白输出格式，不再附上旧题答案；每道题显示实际来源，修改后也会记录。

内置题库只有15道项目示例，未经过任课教师审校；可以导入自己的JSON题库，没有连接外部商业题库。编程题同时提供解题思路与代码。模型不保证原创，建议用时也没有经过课堂验证。

## 三种学科，分别检查什么

|学科|离线可体验的示例|机器能检查什么|还要老师看什么|
|---|---|---|---|
|语文|一年级jqx、习作漫画老师|示范、参考答案、教师检查点是否填写齐全|读音、笔顺、书写、作文内容和课时安排|
|数学|小学乘法、初中一元一次方程|列出的整数、分数四则算式是否算对|题意、图示、单位、推理和讲解|
|信息科技|循环结构|Python代码的实际输入输出、超时等错误|测试期望、讲解和难度|

语文、数学当前示例面向小学和初中；信息科技保留小学、初中、大学选择。学科覆盖不等于已经覆盖各年级的全部教材。自由课题和按参考资料改写，请用本机真实模型。

现场演示建议先按[本机现场演示步骤](docs/本机现场演示步骤.md)走一遍，重点练习用一段新需求生成、错误拦截、保存本机和重开恢复。班情没有提供的人数可填null，表示未知。

## 先选一种使用方式

|你想做什么|怎么打开|
|---|---|
|先看看产品，不安装软件|打开上面的网页，点“体验产品能力”|
|在自己的电脑上用，教案保存到本机|打开 Docker Desktop，双击项目里的 start-docker.cmd|
|不用 Docker，自己选一个教案文件夹|安装 Python 3.11 或更新版本（含 Tk），双击 start-desktop.cmd|

网页体验用的是事先写好的示例模板，不会按参考资料改写；代码运行、数学计算和材料填写检查都按所选学科进行。要让大模型按照你的话重新写教案，请用本机版，并配置自己的 API 密钥。网页首次打开会下载 Python 运行环境，可能需要等一会儿。

## 在本机启动

推荐用 Docker。先下载并解压源码，再打开 Docker Desktop，双击 `start-docker.cmd`。第一次会下载镜像，需要联网。启动成功后打开 [本机页面](http://127.0.0.1:8765)，点“体验产品能力”。

也可以在项目目录运行这条命令：

```powershell
docker compose up -d --build --wait --wait-timeout 180
```

教案确认保存后，在项目的 `teacher_workspace/published/` 文件夹里。聊天记录和历史版本也保存在本机，重启后可以继续用。停止时双击 `stop-docker.cmd`。

详细步骤、密钥填写方法和常见问题见 [Docker本机部署](docs/Docker本机部署.md)。

如果电脑装了 Python，也可以双击 `start-web.cmd`，或运行：

```powershell
python -m app.server --workspace demo_workspace
```

桌面启动器的命令是 `python desktop.py`。打开后输入老师的教案文件夹，点击“打开工作区并开始备课”。它会用浏览器打开操作页面；关闭启动器后服务也会停止。启动器会读取所选文件夹内的小型文本资料，用来帮助备课，请选择专门的教学文件夹。

## 怎样走完一次备课

1. 选择学科、学段、课题和总时长；如果有旧教案，展开“参考教案”，选择docx、txt或md文件，检查读取后的文字并去掉个人信息。填写需求，例如：“给初二备一节40分钟的循环结构课，刚学完条件语句；40人中5人未交作业，3人写了死循环。”
2. 点生成，查看一份教案、两个课堂示范（信息科技为代码示例）、基础/进阶/挑战各一道练习，以及参考答案和评分点。
3. 查看本学科的检查范围：信息科技展示代码输入输出，数学展示算式核对，语文只展示填写完整性。默认循环课有16项代码检查。
4. 检查教案是否适合自己的学生，再逐项点“接受”。全部通过检查、6项都接受后，才能下载。
5. 本机版还可以把文件直接保存到教案目录。系统先列出将修改的内容，老师确认后才写入；已有文件会先备份。

想看编程错误拦截：先选择信息科技，用离线模式生成一版，再输入“故意失败”生成。系统会故意放入一个不会结束的循环。运行检查会失败，此时不能接受或下载。到历史记录恢复通过的版本后，需要重新审核。

## 怎样接入真实模型

把 `.env.example` 复制一份，改名为 `.env`。在 `YUNYUN_API_KEY=` 后填写你自己的阿里云百炼密钥，接口地址要与密钥所在地域、业务空间一致。示例文件中的模型是 `qwen-plus`。

Docker 用户修改配置后运行：

```powershell
docker compose up -d --force-recreate --wait
```

然后在工作台选择“真实模型 API”，再选择“大模型根据需求出题并解答”。调用会使用你账号的额度；没有密钥或调用失败时，页面会提示错误。密钥只放在本机，不要发给别人，也不要上传 GitHub。

不用 Docker 时，还可以运行 `python configure-api.py` 按提示填写。它会把配置存入本机 `.api-config.json`；该文件同样不能分享。如果同时设置了多处配置，程序先读环境变量，再读 `.env`，最后读这个文件。

## 已经检查过什么

三科都已真实调用模型；还检查了Word读取、浏览器学科切换、数学错误拦截、语文待审核提示、代码运行、死循环拦截、下载和文件保存。原有关闭重开恢复测试也保留。桌面启动器已测试输入路径、启动、关闭和重开；系统“选择文件夹”对话框还没有测试。

代码通过测试，也可能有教案写错的地方。例如模型曾把循环结束后的变量值讲错，最后靠逐行对照代码发现并修正。见 [真实AI修正案例](docs/AI修正案例.md)。

目前适合单个老师试用。多人账号、学生端还没做；也不支持随便运行任何 Python 程序。Word只读取文字，不识别图片、口型或书写。正式课堂使用前，仍需要老师检查题目、答案、讲解和难度。
